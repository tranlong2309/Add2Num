LAB 4.2 — Kiểm thử Nâng cao & Rà soát Bảo mật OWASP
Thuộc Section 8 — Ngày 4: Automated tests and quality gates in practice
1. Mục tiêu bài Lab
	•	Phân biệt và sàng lọc các dạng test do AI sinh ra (loại bỏ các test vô nghĩa - tautological tests).
	•	Thực hiện rà soát bảo mật mã nguồn theo danh mục OWASP Top 10 (tập trung vào A01 Broken Access Control, A03 Injection, A04 Insecure Design).
	•	Thực hiện ritual Review PR kết hợp giữa AI summary và đánh giá an toàn từ con người.
2. Các bước thực hiện chi tiết
	•	Bước 1: Tinh chỉnh test case do AI sinh ra
	•	Yêu cầu Copilot sinh thêm các ca kiểm thử âm tính (negative test cases) cho API (ví dụ: gửi dữ liệu rác, inject chuỗi SQL vào trường mô tả). Loại bỏ các test tự khẳng định (assertTrue(true)).
	•	Bước 2: Rà soát bảo mật theo checklist OWASP
	•	Sử dụng bảng kiểm tra OWASP tối thiểu 6 mục cho API Work Order (Ví dụ: Các endpoint danh sách có phân trang/kiểm tra quyền truy cập dữ liệu của user không? Thông tin log có làm sạch PII không?).
	•	Bước 3: Sửa lỗi phát sinh từ rà soát bảo mật
	•	Fix ít nhất 1 lỗ hổng hoặc điểm yếu thiết kế tìm được qua quá trình review, push code cập nhật lên PR.
3. Tiêu chí hoàn thành (Done Criteria)
	•	Hoàn thành biên bản rà soát OWASP checklist tối thiểu 6 mục đính kèm trên PR.
	•	CI build đạt trạng thái xanh sạch với bộ test đã được bổ sung kiểm thử biên.
LAB 5.1 — Tích hợp Hệ thống Cải tiến Vòng đời (Compounding & Lessons Learned)
Thuộc Section 9 — Ngày 5: Integration project and improvement system
1. Mục tiêu bài Lab
	•	Vận hành cơ chế "Compounding" (Lũy tích kiến thức): Biến các bài học kinh nghiệm từ review code hoặc lỗi thực tế thành quy tắc cố định trong hệ thống quy chuẩn của repo.
	•	Xây dựng bảng chỉ số đo lường hiệu quả (KPIs) cho AI-Native SDLC.
	•	Lập tài liệu ghi nhận bài học kinh nghiệm (docs/lessons/).
2. Các bước thực hiện chi tiết
	•	Bước 1: Thiết lập Bảng chỉ số KPI định lượng
	•	Tạo file docs/kpi.md ghi nhận 4 chỉ số cốt lõi trong tuần (Ví dụ: Tỷ lệ lỗi lệch đặc tả trên mỗi PR, Thời gian từ lúc Ready đến lúc Merge, Tỷ lệ CI xanh ngay lần chạy đầu tiên, Số lượng rules được bổ sung).
	•	Bước 2: Viết Bài học kinh nghiệm (Lesson Learned)
	•	Chọn một sự cố hoặc một điểm bất hợp lý do AI sinh ra trong các ngày trước, viết báo cáo ngắn gọn tại thư mục docs/lessons/YYYY-MM-DD-topic.md.
	•	Bước 3: Cập nhật Harness Files
	•	Từ bài học kinh nghiệm đó, tiến hành cập nhật trực tiếp vào file docs/coding-rules.md hoặc Issue Template để ngăn ngừa lỗi tương tự tái diễn ở các chu kỳ sau.
3. Tiêu chí hoàn thành (Done Criteria)
	•	Hoàn thành file KPI (docs/kpi.md) và file bài học kinh nghiệm (docs/lessons/...).
	•	Có ít nhất 1 điểm cải tiến quy tắc hoặc template được cập nhật thành công vào kho lưu trữ.
LAB 5.2 — Mini-Project E2E, RCA (Phân tích Nguyên nhân Gốc rễ) & Close-out
Thuộc Section 10 — Ngày 5: Mini-project E2E, RCA, close-out
1. Mục tiêu bài Lab
	•	Thực hiện toàn bộ chu trình End-to-End (E2E) của một lát cắt nghiệp vụ cuối cùng (Bổ sung tính năng Lọc và Cập nhật trạng thái Work Order).
	•	Thực hành quy trình Phân tích Nguyên nhân Gốc rễ (Root Cause Analysis - RCA) khi cố tình cài đặt một lỗi giả định (hoặc lỗi thực tế) trong hệ thống.
	•	Đóng gói toàn bộ sản phẩm hoàn chỉnh để chuẩn bị báo cáo tổng kết (Capstone Presentation).
2. Các bước thực hiện chi tiết
	•	Bước 1: Phát triển hoàn thiện tính năng phạm vi mini-project
	•	Thực hiện quy trình chuẩn: Issue (Ready) --> Spec PR --> Triển khai Code --> Chạy CI Gates --> Review --> Merge.
	•	Bước 2: Mô phỏng lỗi và viết báo cáo RCA
	•	Cố tình tiêm một lỗi 500 (NullPointerException do thiếu kiểm tra ID thiết bị) hoặc phân tích một lỗi thực tế phát sinh.
	•	Sử dụng biểu mẫu RCA:
	•	Triệu chứng (Symptom): Lỗi 500 khi gọi GET chi tiết.
	•	Nguyên nhân trực tiếp (Direct cause): Thiếu kiểm tra Optional.isPresent().
	•	Nguyên nhân gốc rễ (Contributing cause): Đặc tả API thiếu định nghĩa mã lỗi 404/400 chuẩn, Prompt cho Copilot thiếu ràng buộc xử lý ngoại lệ.
	•	Biện pháp khắc phục & Phòng ngừa (Preventive): Bổ sung test kiểm thử null và cập nhật docs/api-rules.md.
	•	Bước 3: Đóng gói Capstone Pack
	•	Tổng hợp đường dẫn Repository, lịch sử PRs, báo cáo RCA, snapshot KPI và danh sách các file cải tiến harness.
3. Tiêu chí hoàn thành (Done Criteria)
	•	Hoàn thành luồng E2E của mini-project với CI đạt trạng thái xanh tuyệt đối.
	•	Hoàn chỉnh biên bản RCA và đóng gói trọn vẹn Capstone Pack sẵn sàng cho buổi bảo vệ đồ án cuối khóa (5 phút demo mỗi nhóm).
